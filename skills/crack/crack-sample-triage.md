# 样本勘察

## 要回答的四件事

类型（魔数，不是扩展名）· 有没有壳（段表与导入表印证，不是看字符串）· 入口在哪 · 授权线索在哪。

## 路由

| 样本 | 先看哪里 |
|---|---|
| APK | 主包授权类、Manifest 入口 |
| .NET / Unity | 主程序集的 Purchase/License 类 |
| JS / 小程序 | 授权模块、登录态判断 |
| Electron | 主进程校验 |
| PE / ELF | 导入表 + 授权字符串的引用点 |
| 固件 | 提取文件系统再按内容走 |

## 判据

- 类型、壳、入口、授权线索四件事都有**证据**才算勘察完。
- 授权字符串只是**线索**：能在交叉引用里找到谁读它、拿它和什么比较，才算定位到校验。
- `UPX!`、`.vmp`、`mscoree` 只说明"像"，壳可以伪造也可以嵌套。
- **换路**：主流脱壳路线都试过仍拿不到可读代码，作为卡点上报，不在壳上耗。

## 交付

一句路由结论 + 依据。
