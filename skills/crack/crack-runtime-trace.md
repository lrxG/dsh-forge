# 运行时观测

## 看到什么才算数

- 真实入参与真实返回值，并且能和静态定位到的类/方法对上；对不上先怀疑 hook 点选错。
- 反调试/反 root 是"能不能观测"的前提，不是分析对象：进程自杀、hook 挂不上时先解决它，别在挂不上的前提下推断逻辑。
- 网络校验用抓包看请求与响应；本地改判断只能骗界面，服务端拒绝就是没破。

## 判据

- 强制返回 `true` 后"解锁了"，只证明这个点被调用过，**不证明它是唯一判断点**——最容易当成结论的一条。
- 日志里的字符串可能是混淆后的中间值或缓存副本，要换入口或二次调用交叉验证。
- 观测结论要附回显，不能只写"已确认"。

## 交付

验证结论、反调试清单、运行时拿到的秘密（脱敏）、给 patch 的实测建议。
