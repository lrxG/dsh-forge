# 目录与文件爆破（先定基线，再谈命中）

这条路的价值不在"扫出多少个 200"，在**筛掉多少假命中**。基线错了，后面全是噪声。

## 什么时候扫，什么时候别扫

- **值得扫**：站点存活、指纹模糊、业务像有后台或文件管理；或者已有线索指向某类文件（备份、配置、文档）。
- **别扫**：目标是纯 API 网关且已给出接口清单；或者你已经能从 JS、接口文档、报错里直接读到路径——那比字典准。
- **字典**：通用大字典铺面，单位相关的词（品牌、拼音缩写、业务名）自造小字典补漏，后者命中率通常更高。
- **字典是增量资产**：遇到的新路径习惯、备份命名、导出接口前缀，随手记进字典；维护以新增为主，
  旧字典只做去重与补充，不要每次重建。

## 判据：什么算真命中

三条同时成立才算：**状态码不在排除集**、**响应长度或内容与软 404 基线不同**、**内容与路径语义相符**
（源码目录真能取到仓库结构、压缩包真能解、后台页真有登录表单）。

基线只能来自**同一 host 上随机不存在路径的实测**——不能猜，也不能拿别的站的长度套。

反幻觉：

| 现象 | 含义 |
|---|---|
| 命中率接近 100% | 通配或软 404，先修基线，不是战果 |
| 所有路径长度一样 | 反代统一错误页，长度判断失效，改看内容差异 |
| 302 跳到登录页 | 说明有统一入口，不等于这里存在后台 |
| 稳定 403 | 可能存在只是无权，值得换方法，但不算命中 |

## 降噪与自保（判据，不是参数表）

- **先定基线再开跑**：软 404 不滤掉，扫多少都是白扫。
- **限速看信号**：出现成片 403/429 就是被限，降速或停；不要加大线程硬顶。
- **危险路径不碰**：登出、重启、关机、删除、重置这类会改状态的路径，字典里遇到也跳过——会造成业务中断，且演练不记分。
- **被封就换资产**：同一资产被封多次记 abandoned，转下一个，不要在一个点上反复试。
- **内网目标走隧道**：本机直连不到的内网站，先确认隧道真能到，再扫。

## 换路条件

- 同一字典两轮无新增 → 换字典或换目标，不要加线程；
- 命中率异常高 → 修基线，不是换字典；
- 连续被限速 → 换被动渠道（JS、接口文档、报错、源码泄露）找路径；
- 只出统一错误页 → 这个站不适合爆破，转业务面。

## 命中之后

扫到东西只是开始，**每一类命中值不值得跟、怎么确认是真的**，见 `dir-secrets`。
后台入口交给 `credential-attack`，接口清单交给 `exposed-services` / `object-and-tenant`，上传点交给利用链。

## 落库

隐藏路径本身不计分；**拿到东西的路径**才落库：入口记进资产 `surface`，泄露物记凭据或漏洞，关键动作写一条链步骤。
字典与原始结果放 `runs\`，报告要能复现。
