# 浏览器自动化

普通页面先用请求工具取源码；**内容由 JS 生成、要看登录态、要点击填表上传、要抓登录后的请求**，
或者**取数那条路自己断了**（搜索后端报 401、页面被 Cloudflare 挡、只拿到 JS 外壳）时才上浏览器。
「不知道网址、得先找」也是它——搜索引擎的结果页和普通页面一样开、一样读。

## 三种跑法，按要不要交互分

| 需要什么 | 用什么 |
|---|---|
| 只知道要查什么、不知道网址 | `browser` 开搜索引擎，从快照里挑结果，再逐个开 |
| 只要渲染后的 DOM、截图、PDF，公网页面 | 本机 Chrome/Edge 的 headless 模式（Windows 上都在默认安装路径，不必另装 chromium） |
| 要等待、点击、填表、多标签 | `browser` 工具：`open` 带 `new_tab`，`tabs` / `switch` / `closetab` 管页；用完关掉，别堆着 |
| 要登录态、要真实指纹、要和操作者日常浏览器隔离 | `browser` 工具（独立 profile，headed） |

headless 的关键参数是**等多久再取页面**：给太短，SPA 只交出骨架屏；给太长，白等。
`browser` 工具第一次登录后 profile 会保留，下次不用重登；它和操作者日常用的 Chrome 相互隔离，
两边可以同时开。要登录态就登在这个 profile 里，不要去碰操作者自己那个 Chrome。

## 抓前端接口清单

渲染后的 DOM 里通常已经带着路径常量；JS bundle 里更多——前端路由与接口地址常埋在那里。
做法是从 DOM 与 bundle 里提路径、去重、成清单，再拿清单去打；提出来的是**候选**，判据见下节。

## 判据：什么算抓到了

- 渲染成功的判据是 **DOM 里有业务数据**（列表项、价格、资源 id），不是命令返回成功，也不是标题正常。
- 正则提出的接口路径只是字符串，不证明端点存在：要么在前端调用处看到它的用法，要么实际请求一次。
- 复用 profile 拿到的是旧 Cookie，判据是页面里出现**登录态内容**，不是返回 200。
- 截图/PDF 只证明"当时长这样"，等待不够时会停在加载中，不能当内容完整。
- 被 Cloudflare/验证码挡住，或取回来只有 JS 外壳，就换路：交互式驱动 → 本机真实浏览器（`browser`）→ 退到静态读 bundle。
  三种都不成才算这条路不通，别在同一个页面上反复试。

## 落盘

URL/标题写回资产库；接口清单与页面快照落工作目录的 `runs/`，并在攻击链里引用是哪一个。
页面内容可能含敏感数据，只落 `runs/`，不写进资产库。
