# 子域接管：什么算成立（低频：只有出现候选才读）

悬空的定义只有一条：**平台自己说"这个域名没绑到我这儿"**。
任何通用 403/404 都不是证据。判据收不严的代价是成批假报告——对账号信誉的伤害比漏报大。

## 两条硬判据

1. **语义**：响应体里有没有一句平台自述"这个域名/站点/项目在我这儿不存在"？
   不是通用 403/404，是平台明确说不认这个域名。
2. **来源**：这句话是不是平台边缘自己发的？看 `Server` / `Via` / `X-Served-By` 这类头，
   以及回包里出现的边缘 IP 是否属于该平台 ASN。源站也能伪造同样的字符串。

两条都成立才算悬空。**下面的表是样本，不是白名单**：表里没有的平台，按这两条原则自己判。

## 见过的信号样式（会变，按语义判）

- 对象存储：`NoSuchBucket` / 桶不存在——**`NoSuchKey` 不算**，那是桶在、对象不在。
- 静态托管（GitHub Pages 类）：页面不存在**且**目标账号本身不存在；账号还在就抢不到。
- 应用平台（Heroku / Vercel / Azure 类）：`no such app` / `deployment not found` / `web app not found`；
  **Azure 的"Web App Unavailable"是停用不是删除，不算**。
- 边缘服务（Fastly 类）：`unknown domain` + `please check that this domain has been added`，最硬。
- 弱信号（Netlify / Firebase 类）：只有一句通用 not found，必须配合目标探测确认。

## 第二步：确认是平台边缘直出

1. 响应头有无平台边缘标识（`Server` / `Via` / `X-Served-By` / `X-Cache` / `X-Amz-Cf-Id`）；
2. 回包里的边缘 IP 或节点名，查 ASN 是否属于该平台；
3. 多打几次看节点是否变化——**多个不同边缘节点给同样拒绝**，比单节点硬得多。

Fastly 那类回包要看四个字段：状态行、`Server`、`X-Served-By`、正文里的 `Details` 与 IP。四个一起留。

## 四层证据：悬空 ≠ 接管 ≠ 有危害

**这一节最关键。** 悬空是技术状态，不等于可提交漏洞；不要用上层结论推下层。

| 层级 | 回答什么 | 没拿到时 |
|---|---|---|
| E1 状态 | DNS/CNAME 是否指向失效或未配置的服务 | 什么都不成立 |
| E2 控制权 | 能否证明该服务可被他人认领 | 记"疑似悬空"，不提交 |
| E3 关联 | 该域名是否被目标真实功能/流程使用 | 只能记 metadata（低危） |
| E4 影响 | 在**不伤害用户**前提下能否证明影响 | 不能写 high/critical |

**E3 的价值差得很远**：官方 App 真实调用 ≈ 强；登录/找回密码/通知邮件域名 ≈ 高；
页面 JS 里出现过 ≈ 中（首页搜不到不代表没有，可能在懒加载 chunk、邮件模板、客户端里）；
只能证明"技术上可认领" = 那是 E2；"接管后可以钓鱼" = **推演，不是证据**。

教训：三个悬空域名在 340KB 首页里出现 0 次，当时仍按 high 记，理由是"接管后可钓鱼"——
那正是推演。正确做法是记 metadata(low)，把"继续找 App/邮件引用"写进下一步。

## 验证纪律

只发 GET；不注册 service、不建桶、不上传；未授权前不实际接管；不投放内容、不影响真实用户。
报告只写"可被接管，进而可能影响 X（基于 Y 证据）"——先有 Y 才写 X。
同时探一个已知正常的对照域名，确认探测器本身没坏。

## 排除逻辑（看起来像，其实不是）

| 响应 | 为什么不算 |
|---|---|
| CloudFront 通用 403 | 对所有未配置 Host 的标准拒绝，**没有可靠应用层悬空信号**，做不了侧证就记不可判定 |
| `NoSuchKey` | 桶存在，只是路径不存在 |
| GitHub Pages 404 但账号在 | 账号占着就抢不到 |
| 任何 502/503 | 上游故障，不是解绑 |
| Azure 403 Unavailable | 应用停用，域名仍绑着 |

**判不出来的记"不可判定"，不进漏洞库。** 记不可判定比记假漏洞安全得多。

## 归属确认：报告交给谁

同一个响应属于不同 program 就是两份报告。交之前确认：program 的 in-scope 与通配符覆盖、
域名注册人与证书 CN、该域名历史归属。同一批响应可能分属两个买家。

## 报告要素

受影响 host 与完整 CNAME 链；平台侧原始报文（状态行+头+正文前 400 字节）；
边缘 IP 的 ASN 归属；接管方式（在哪个平台建什么记录）；影响与修复。
