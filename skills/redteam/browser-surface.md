# 浏览器面（采样点在别人浏览器里）

这一面的判据只有两条：**我的代码能不能在受害者浏览器里执行**，**已登录的人能不能被我驱动发请求**。
"页面上出现了我的字符串"是回显，不是 XSS；"接口能吃我的参数"是功能，不是 CSRF。

## XSS：先判上下文，再判执行

| 回显位置 | 需要的条件 | 常见误判 |
|---|---|---|
| HTML 正文 | 尖括号未被转义，能插入标签 | 只回显在属性值里却当成正文 |
| 属性值 | 能闭合引号或注入事件处理器 | 引号被转义仍写"可注入" |
| `<script>` 内的 JS 字符串 | 能闭合字符串或注入换行 | 转义了 `<>` 却漏了引号与反斜杠 |
| JSON 响应 | 前端是否把内容塞进 innerHTML | 只看响应体不看消费点 |
| 富文本/Markdown | 渲染器是否允许该标签与属性 | 编辑器过滤了但展示端没过滤 |

**执行证明**：用只有我能生成的标识触发一次可控行为（发起带标识的请求、留下控制台可读的标记），截图 + 原始请求一起记。
弹窗不算证据——可能被浏览器策略拦，也可能只是弹了但没执行。

**存储型要判"谁看得到"**：管理员面板里的存储型与管理端越权是两种严重级，先判受害者是谁，再定级。
**DOM 型**要同时指出 source（location、hash、postMessage、存储）与 sink（innerHTML、eval、脚本拼接），
两者不连通就不成立。

## CSP：有策略不等于打不了

- 看的是**可注入位置是否被 nonce/hash 覆盖**，不是看有没有 CSP 头。
- 只上报模式（report-only）不拦任何东西，不算防护。
- 严格 CSP 下仍可能成立：`base-uri` 缺失、允许的内联 script 属性、允许的白名单域上存在可控脚本。

## CSRF：三个条件缺一不可

1. **凭证自动带上**：看 Cookie 是否有 SameSite 限制。`Lax` 下导航型 GET 仍会带，别一律认为不行。
2. **参数可预测**：全部参数都能由我构造，没有一次性令牌。
3. **无二次校验**：不校验 Referer/Origin，或校验可绕过；关键动作没有重新认证。

JSON 接口要看是否强制 `Content-Type`，以及是否用自定义头做 CSRF 防护——这两条任一成立，普通表单就打不动。
判据是**状态真的改变了**（数据被改、订单被创建），不是"请求发出去了"。

## postMessage 与跨窗口

- 接收方缺 `origin` 校验 + 收到数据后进了危险 sink（innerHTML、eval、跳转）= 成立。
- 只缺校验但数据只用来显示、无危险消费点 → 记为配置问题，不是漏洞。
- 发送方把敏感数据发给 `*` 是信息泄露，先判数据敏感度再定级。

## 换路条件

- 三处回显点都做了同一种转义 → 这个参数不是注入点，换参数或换面；
- 严格 CSP + 无可注入位置 + 无白名单脚本 → 转 CSRF、点击劫持、客户端存储；
- 只回显不执行、且消费点确认安全 → 记为内容问题，不要写成 XSS；
- SameSite=Strict + 自定义头 + Origin 校验同时存在 → 这一面基本封死。

## 落库

每条附**原始请求 + 响应 + 执行证据**（截图或带标识的回连），并写清受害角色（匿名/普通用户/管理员）。
存储型注明触发页面与受害者范围；CSRF 注明受影响动作与是否需要受害者已登录。
