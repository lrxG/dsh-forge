# 执行面（怎么证明真的执行了）

执行类漏洞最大的风险不是打不进去，是**把"它说它执行了"当成执行了**。这一篇只解决一件事：
什么证据能证明命令真的在这台机器上跑了。

## 判据：什么算执行成功

| 证据 | 算成立 | 不算 |
|---|---|---|
| 回显里出现只有目标才有的东西（主机名、内网地址、本机文件内容、环境变量、靶标 flag） | 真执行 | 回显里是模型自己编的数字、"已执行成功"之类的话 |
| 时间差与注入的等待时间一致，且重复两次都一致 | 真执行（无回显时的主要手段） | 偶发慢一次 |
| 外带通道收到目标发来的请求（带只有我能生成的标识） | 真执行 | 只是 DNS 解析、只是公网连通 |
| 写文件后能从静态路径读到内容 | 真执行 | 只回 200 |
| 沙箱内拿到了身份 | **只算沙箱**，不等于目标主机 | 沙箱里 `uid=0` 当服务器权限 |

**交叉验证**：把自己注入的标识（随机串、时间戳、只有我能算出的值）放进命令，看它出现在回显里。
模型能编造 `id` 的结果，但编不出我刚生成的随机串。

## 冲突证据怎么采信

同一件事有多份说法时按这个顺序取信，后面的不能推翻前面的：

运行态行为 → 抓到的网络流量 → 正在服务的资产 → 当前进程配置 → 持久化的目标状态 → 生成出来的产物 → 已检入源码 → 注释与死代码。

用源码解释运行态，不推翻运行态。看到回显不等于成立：差分、可复制的原始包、假值对照，至少一条成立；否则只记为候选。

## AI / Agent 类目标

1. 先找有没有执行工具（命令、代码、文件、浏览器、数据库），再找"我是谁"的接口；
2. 没有身份接口也要打——它可能只是没暴露，不代表没有工具；
3. 看它读不读我自己写的文件（工作区、配置、技能文档），能读说明拿到的是真实文件系统；
4. 能跑命令但落在临时沙箱（每次请求目录都变、重启即清）→ 记为半条，接着找持久化路径；
5. 别被"模型拒绝"当成"没有能力"：换个说法、换个工具、换个参数位置再试，能力面与话术是两件事。

## 模板与表达式

先**证明可控**（下一次请求的行为变了、页面里出现了我注入的标记），再谈执行。
只有"报错里带了我的输入"是回显，不是执行；只有"模板渲染出我的字符串"是渲染，不是命令执行。
有污染类原语（原型链、配置合并）时，要找的是**下游有没有会把它变成执行的消费点**，没有就停在这一层。

## 客户端协议

注册了自定义协议的桌面客户端：协议参数里能填网址，就先看它加载页面时有没有暴露宿主能力
（预加载脚本、渲染进程能力、内部桥）。能弹窗但拿不到宿主能力 ≠ RCE，只能算存储型问题。

## 换路条件

- 三种注入位置（参数、请求头、文件内容）都无差分 → 这个入口不是执行面，换入口；
- 有回显但内容与注入不符 → 是缓存或模拟响应，换目标重测；
- 沙箱每次都换且拿不到宿主信息 → 记为"沙箱内执行"，不再往下钻；
- 模板能渲染但找不到消费点 → 停在渲染层，记录证据，不要写成 RCE。

## 执行位置
本机经代理发；外带通道用自己控制的服务器（技能 `vps-reverse-shell`）。
执行类 payload 一律先做**无害验证**（读文件、打印主机名），验证通过再谈下一步。

## 落库
执行类必须附**原始请求与回显原文**；沙箱类在证据里写明"沙箱内"，不要混进服务器权限；
拿到主机权限后按 `server-host` 记分，沙箱不算主机权限。
