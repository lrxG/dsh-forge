# 定级

定级只回答一个问题：**这条东西被利用后，对方实际拿到了什么**。不看它叫什么名字，也不看扫描器给的标签。

## 三个坐标

| 坐标 | 问什么 |
|---|---|
| 拿到了什么 | 服务器权限 / 数据库权限 / 后台管理员 / 内网入口 / 某类数据 |
| 要多难 | 未授权 / 只要普通账号 / 需要一次交互 / 需要已控主机 |
| 影响多大 | 单台 / 同段同构的一批 / 全域或核心库 |

**同一件事换前提就掉两档**：未授权的命令执行是 critical；需要先有后台管理员才能触发的命令执行
只是 high 甚至 medium——因为它没有增加对方已经有的能力。

## 常见档位长什么样

| 档 | 形状 |
|---|---|
| critical | 未授权直达命令执行；拿到域控或核心数据库；任意文件写入已证明能落成执行；能直接读全量用户数据 |
| high | 需普通账号或一次交互才命令执行；SQL 注入拿到数据或系统权限；后台管理员权限；越权到他人账号的完全控制 |
| medium | 越权读到他人有限数据；SSRF 能探内网但读不到文件；管理端的存储型 XSS；配置或备份泄露含有效凭据 |
| low | 要高权限前提才成立的提权；反射型 XSS；目录列举；版本与组件暴露 |
| info | 只能说明"这里是什么"，拿不到任何东西 |

## 压误报的四条

- **扫描器报的是 candidate，不是漏洞**：没复现、没证据的先按 candidate 存，不给档。
- **同一根因算一条**：一个模板在八十个地址上命中，是一条漏洞影响八十处，不是八十条。
- **不能重复的不给高档**：只在某个瞬间成立、或依赖对方临时配置的，降一档并写清前提。
- **自研组件、内网系统不因"外界不知道"提级**：影响面靠事实，不靠稀有度。

## 和得分分开

得分是靶场规则（拿分点、口径标签），报告定级是给人判断风险用的，两者会不一致：
一条按靶场规则不值分的"能读全量数据"，在报告里仍然是 high。写 `gained` 用得分口径，
写 `severity` 按影响，不要让一边去将就另一边。

## 落库

定级要能自证：**影响 + 前提 + 复现证据**三样，缺一样就降档。
同一靶标内同类问题的定级要一致，否则报告自相矛盾，看报告的人只会信最低的那条。
