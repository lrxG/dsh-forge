# 被动信息收集（不发包）

## 何时用
- 刚拿到单位名称 / 主域名 / 一个 IP，**还不知道资产面有多大**；
- 主动扫描已经触发封禁，需要换不接触目标的路子继续扩面；
- 要给后续主动扫描定范围（范围之外的资产不进扫描队列）。

## 判据：什么算拿到了东西

| 信号 | 含义 | 下一步 |
|---|---|---|
| 证书透明（crt.sh / certspotter）里出现**同一张证书带多个域名** | 最可靠的资产扩面来源，常能挖出未备案、内部命名的子域 | 逐个解析，能解析且证书匹配的进资产库 |
| WHOIS / 备案信息里有**同一注册人、同一邮箱、同一电话** | 说明还有其它主体下的资产，但归属需要人工确认 | 记成待确认线索，不直接当靶标 |
| 子域解析到**与主站不同的 C 段** | 可能是云上独立部署，攻击面与主站完全不同 | 单独建资产，别和主站混在一起测 |
| 只拿到泛解析（`*.domain` 全部解析到同一 IP） | 说明该域名走通配，DNS 枚举基本失效 | 停止枚举，转证书透明或被动 DNS 库 |
| 被动源里同一个 IP 挂着大量无关站点 | 共享主机/CDN，打它不属于目标 | 直接排除，别浪费预算 |

**换路条件**：连续两个数据源对同一域名给出的资产集合没有新增，就该停——继续换被动源只会重复消费配额。

## 各来源的价值差异（按可靠性排）

1. **证书透明**：唯一能反映"真实签发过的域名"的公开数据，最难被伪造；
2. **被动 DNS**（SecurityTrails / VirusTotal / 微步等）：能看到历史解析，适合找已下线但仍可访问的旧资产；
3. **搜索引擎与备案信息**：适合补"单位主体"层面的横向资产（同一单位的不同域名），噪声大；
4. **公开代码仓库与文档**：适合找泄露的内部域名、测试环境地址、硬编码 IP，命中率低但价值高。

判断一个来源值不值得继续投入：**它的数据能不能反过来验证**（能不能解析、能不能连、证书对不对）。
只能给出"可能存在"而无法验证的来源，记一行线索就走。

## 执行位置
全在本机执行。这些源都不接触靶标本身，但请求也要走代理，避免把本机出口暴露给第三方平台。

## 落库
- 每个能解析的域名/IP 入资产库，来源标 `passive`（面板据此区分主动扫描结果）；
- 拿不到解析的线索（只有名字没有地址）记进该靶标的待确认清单，**不要入资产库**，否则后面会反复重测不存在的东西；
- 资产落库用批量入库。
