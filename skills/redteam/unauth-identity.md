# 未登录身份面（不登录换到身份）

**这一类不是"绕过登录"，是找到系统自己签发票据的地方。** 真正的入口往往不在登录表单后面，
而在登录**之前**：签发、联合登录、刷新、验证码、回调、分享、体验、匿名会话。

## 判据：什么算换到了身份

| 拿到什么 | 算成立 | 不算 |
|---|---|---|
| 一张票（token / JWT / cookie / userSig / 临时密钥） | 用它打"我是谁"的接口，返回的**是别人**的手机、姓名、角色 | 只回游客空号、只有自己刚建的空对象 |
| 可枚举的身份字段 | 换成邻号后，列表或详情出现**他人**的业务数据 | 换号后返回空、或仍只出公开内容 |
| 空值/假值被接受 | 空串、空对象、假签名能过校验，且回包带真实业务数据 | 空值也回"请登录"；报错只是字段校验 |
| 一次性的验证/重置/绑定 | 真改掉了别人的口令或绑定（**过了立刻改回**） | 提示成功但登录时口令没变（没写库） |

**唯一硬标准**：回包里出现**他人的**、非公开的、真实存在的业务数据。
"接口返回 200"、"拿到了 token"、"字段被接受"都不算。

## 找入口的顺序

1. **从前端找**：打包 JS 里的接口清单、写死的产品号/租户/演示账号、签名盐、公钥、mock 数据里的密文 id；
2. **从回包找**：任何新出现的 id、下载地址、内网 host、角色字段，立刻进清单再打一枪；
3. **按语义找**：登录、刷新、发签、联合登录、回调、验证码、重置、邀请、绑定、体验/演示入口；
4. **从差别找**：同一个业务接口，页面走的是需登录的那条，同网关常另有一条 `unlogin` / `guest` / `n` 前缀或独立身份子域。

## 判据：哪些位置值得换着打

同一个接口报"缺参数"时，参数位置本身就是一条线索：query 不吃就搬进 body，body 不吃搬进 header，header 不吃搬进 cookie。
真正缺参数会在三个位置都缺；只认某一个位置，说明那是**鉴权取值点**，换位置往往就绕过了。

## 换路条件

- 三种位置都试过仍报缺参 → 真缺参，不是洞；
- 票拿到了但任何业务接口都回未授权 → 票是空号或已失效，回到签发口看是否要带业务 id；
- 连续两处签发口都只签游客 → 这个产品没做错，转对象面（技能 `object-and-tenant`）；
- 目标有验证码/滑块且必须真机 → 交给用户手工完成一次，拿到会话后转对象面，不要在验证码上耗。

## 执行位置
全部在本机经代理发；不发破坏性请求，改密/改绑类只在"拿掉旧校验"这一层验证，通过后立刻改回。
别人的 SSO/IdP 页面本身不审，只审目标自己的签发与回调。

## 落库
拿到票据与越权对象后：漏洞条目（未授权/接管）+ 原始请求证据 + 凭据条目（写清来源是哪个签发口）。
账号权限只有**实测登录成功**才记分；自己注册的号不算。
