# 外部信息收集流水线（顺序比工具重要）

把"一个域名"变成"一份值得打的存活资产清单"。顺序是**枚举 → 解析 → 端口 → 存活 → 分类**，
每一步都为下一步削范围；任何一步如果不缩小范围，就该换参数而不是继续往下跑。

## 每一步的判据与停止条件

| 阶段 | 有效信号 | 该停/该换路的信号 |
|---|---|---|
| 子域枚举 | 被动源之间出现**新增**子域；证书透明里带多域名的证书 | 两轮不同来源结果不再新增 → 停止枚举 |
| 解析存活 | 域名解析到真实 IP，且 IP 不在 CDN 共享池 | 全部解析到同一批 CDN 边缘 IP → 直接拿源站线索走别的路，别再扫这些 IP |
| 泛解析过滤 | 随机子域解析失败（说明没有通配） | 任意随机子域都能解析 → 通配域名，DNS 爆破全部失效，只用证书透明与被动 DNS |
| 端口扫描 | 非标准端口上出现 HTTP/数据库/远程管理 | 全端口只开 80/443 且是同一套反代 → 转去核应用层，不要在端口上继续耗 |
| HTTP 存活 | 返回差异化内容（标题、状态码、长度都不同） | 所有路径返回同样长度与状态码 → 软 200，状态码判断失效，改看响应体差异 |

**关键判断**：资产梳理的价值不在"发现多少个"，而在"筛掉多少个不用打的"。
一个 /24 扫出 200 个资产，其中 180 个是同一套负载均衡器，这份清单等于只有 20 个。

## 工具选择（按场景，不按固定流程）

- **铺面**（找出单位名下到底有多少资产）：测绘平台最全，能覆盖未备案与同主体资产；
- **子域扩面**：被动枚举覆盖广，爆破只在确认无通配后才有意义；
- **解析存活**：批量解析工具都能做，关键是**同时做泛解析过滤**，否则后面全是噪声；
- **端口**：先 top 端口快扫，只对"有存活信号"的主机做全端口——不要对整段做全端口；
- **HTTP 存活与指纹**：一次带上标题、状态码、技术栈、服务器头，避免重复请求。

工具路径一律取 preflight 解析出的绝对路径。

## 分类优先级（交给下一步时按这个排）

1. **非标准端口 + 有标题 + 技术栈老旧**：最可能是没纳管的独立系统；
2. **测试/预发/旧版域名**（`test` `dev` `uat` `pre` `staging` `old` 等前缀）：防护弱、数据真；
3. **同 C 段但不同域名的站点**：可能是同一单位未备案的系统；
4. **主站在 CDN 后面、子域直连源站**：子域才是真实攻击面；
5. 其余主站资产放最后——它们通常有 WAF 且被反复测过。

## 两条不可省的约束

- **主动行为先定范围**：端口扫描与子域爆破都会留下痕迹，范围没定清就不要开跑；限速起步不要拉满，出现成片 403/429 就是被拦，降速或换面。
- **结果边跑边落**：每阶段结束就把结论写进库，不要攒到最后一次性写——中途断了等于白跑；最终汇报给数字（子域数 / 存活 IP 数 / 开放端口数 / 存活站点数 / 高优先级几条），没有数字的结论等于没做。
