# 内网横向（判断往哪走，而不是走多少台）

横向的目的只有两个：**拿到核心系统**（域控、堡垒机、运维平台、数据库集群、代码仓库、备份系统），
以及**拿到更多可复用的凭据**。打十台普通主机不如打一台能通向域控的主机。

## 判据：哪些主机值得动手

| 信号 | 含义 | 优先级 |
|---|---|---|
| 主机上挂着运维/堡垒机/监控平台 | 往往是通向全部机器的钥匙 | 最高 |
| 同一台机器上同时开放 SMB、WinRM、RDP、数据库 | 多协议可达，凭据复用成功率高 | 高 |
| 主机名或域信息指向 DC、CA、备份、Jenkins | 直接就是得分点 | 高 |
| 本地管理员口令在多台主机上可复用 | 同模板批量装机，一台破全段破 | 高（先试这个） |
| 已控主机能到但凭据不通的主机 | 需要新的凭据，不是新的攻击面 | 低（先去搞凭据） |
| 普通员工终端、打印机、摄像头 | 拿了也走不远 | 最低，除非它挂载着凭据 |

**核心判断**：横向的瓶颈是**凭据**，不是可达性。拿不到新凭据时，继续横向只是在写"我也能连"。

## 两条路的分工

- **凭据复用**（命中率最高）：一个口令试所有主机与协议；本地管理员口令复用；域账号试共享与业务系统；
- **哈希传递**（不破解直接用）：拿到 NTLM 哈希就能横向，**不要为了"拿到明文"去等破解**；
- **票据与委派**（能直通域控）：只有在已确认域环境、且拿到域内普通账号后才值得投入。

顺序上：**复用 → 哈希传递 → Kerberos 攻击 → 漏洞利用**。倒过来做的人通常在浪费时间。

## 凭据转储的判断

| 信号 | 含义 | 动作 |
|---|---|---|
| 能读 SAM/LSA 但读不到域内哈希 | 只是本地管理员 | 用这批本地哈希横向，别急着打域控 |
| 能执行 DCSync | 已有复制权限，等于域内最高权限 | 立刻停手收尾，不要再刷动作 |
| 转储触发告警/进程被拦 | EDR 在盯 LSASS | 换更安静的手法，或干脆不做 |
| 抓到的哈希与已有账号重复 | 口令复用的证据 | 直接横向，比继续 dump 有价值 |

## 隧道与位置

内网目标不可直连时，先建隧道再打（技能 `suo5-tunnel` / `chisel-tunnel` / `frp-tunnel`）。
注意两件事：**隧道只代理 TCP**，Kerberos 的 UDP 部分与反连场景要走端口映射；
**隧道是瓶颈**，并发一高就大面积超时，很容易被误判成"目标不通"。

## 什么时候必须停

1. **账号开始被锁**：域账号连续失败会锁号，锁一次可能毁掉整条横向路径；
2. **已经拿到核心系统**：目标达成，继续刷主机只增加暴露风险；
3. **每台新主机都触发告警**：说明防守方已经发现，收手比再打一台有价值；
4. **横向路径已经绕出本次范围**：技术上可达不等于可以打。

## 纪律
- 优先安静手法，噪声大的手法（落地服务、触碰 LSASS）只在必要时用；
- 禁止破坏性动作：不停服务、不改配置、不删日志；
- 每台新主机、每次成功登录、每条凭据都要登记，**并写清来源路径**——
  否则后面无法判断这条凭据还能复用到哪里。
