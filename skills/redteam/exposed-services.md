# 暴露服务（直连取数与写马）

暴露的数据库与中间件是**不用漏洞、不用爆破**就能拿到权限的点：连上去就是数据权限，写文件就是服务器权限。
代价是**一旦误判就会在别人的生产库上动手**，所以判断"到底有没有鉴权"比执行利用重要。

## 判据：真未授权 vs 被别的层挡住

| 观察 | 含义 | 动作 |
|---|---|---|
| 返回了服务的真实响应（版本号、集群信息、keyspace） | 真没鉴权 | 继续，但只读优先 |
| 连接被重置或立刻断开 | 有网络层设备在拦 | 不是未授权，换端口/换路径再确认 |
| 返回统一错误页或登录页 | 端口通了但服务前面有代理/网关 | 记录为"端口开放但不可直连"，不要当未授权 |
| 能读但不能写 | 只读权限 | 拿 `db-credential` 这档的分就够了，不要再折腾写 |
| 读得到数据但都是空库/测试库 | 撞到了蜜罐或测试实例 | 标记，不要在它上面做任何写操作 |
| Web 接口少一个鉴权参数就返回全量数据 | 真未授权接口 | 立刻截图/存响应作为证据 |

**最关键的判断**：能不能**稳定复现**。一次成功可能是缓存或边缘节点，连续两次一致才算确认。

## 动手顺序（先轻后重，每步留证据）

1. **只读确认**：查版本、查配置、列库表，不改变任何状态；
2. **取数据**：只取能证明危害的那部分，统计条数；
3. **写权限**：只有在"确认这是演练目标、且用户接受影响"之后才做；
4. 每一步的原始命令与响应都要留档，否则报告里无法复现。

## 写操作的破坏性判断

| 写手法 | 影响面 | 风险 |
|---|---|---|
| 写 WebShell 到站点目录 | 低（多一个文件） | 可能被查杀、可能触发告警 |
| 写 SSH 公钥 | 低 | 等于给自己留后门，清理时必须删 |
| 写计划任务/服务 | 中 | 可能被执行多次，可能影响业务 |
| 改配置（目录、持久化路径） | 中-高 | 改完必须恢复，否则业务可能异常 |
| 主从复制类利用 | 高 | 容易打崩实例，只在明确授权时用 |

**规则**：只读就能拿分的，绝不写；必须写的，选影响面最小的一种，并且**记下如何恢复**。

## 常见误判

1. **把端口开放当成未授权**：端口通不等于服务没鉴权；
2. **把浏览器缓存/代理返回当成"读到数据"**：换个新会话再确认一次；
3. **在生产库上跑全量遍历**：会阻塞服务，用增量遍历；
4. **把"能连上"写成"拿到数据库权限"**：得分口径是按实际拿到的权限算，不要虚报条数。

## 执行位置
互联网目标从本机打，内网目标先建隧道再从隧道里打。走隧道时降并发，
隧道拥塞表现出的超时很容易被误读成"服务不可达"。

## 落库
- 未授权本身先落一条漏洞，带上原始响应片段作为证据；
- 拿到数据权限后记分时**必须写实际条数**，条数是得分依据，虚报等于报告造假；
- 写进去的入口（马、公钥、任务）都要登记，**并写清清理方式**——演练结束要能复原。
