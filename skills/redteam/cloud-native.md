# 云与容器

云上值钱的不是"这台主机有什么漏洞"，是**权限配置**：一份能列资源的凭据、一个能读到元数据的 SSRF、
一个权限开着的桶。容器也一样——值钱的是控制面，不是那个容器本身。

## 先确认自己在哪

| 现象 | 结论 |
|---|---|
| 元数据地址可达、主机名与错误页带厂商特征 | 云主机 |
| 主机名是随机串、进程极少、根分区很小 | 容器内 |
| 能看到宿主进程、多块磁盘、能读宿主目录 | 已在宿主或特权容器 |

分不清厂商不耽误下一步：**先确认元数据能不能碰到**，这决定 SSRF 值不值钱。

## 云：三类入口，价值从高到低

| 入口 | 判据 | 值多少 |
|---|---|---|
| 凭据（AK/SK、临时令牌、实例角色） | 能列资源才算有效；只报权限错是"存在但没权限" | 最高：一把钥匙，且常常比主机权限大 |
| 元数据服务 | 从目标侧能读到实例角色的临时凭据 | 高：把 SSRF 从"能探内网"变成"拿到云权限" |
| 对象存储 | 匿名能列 / 能读 / 能写，是三种完全不同的事 | 列 > 读 > 写；能写单独按高危算 |

**假路**：只返回 403 的桶、只有 SDK 报"签名不对"的地址、厂商通用错误页——都不证明任何权限。

## 凭据怎么判有效

- **能列**：列出桶 / 实例 / 用户，就是有读权限，按已控算。
- **能读单条**：已知资源名能取到内容，说明能读但不可枚举，价值低一档。
- **只能动自己**：只能改自己的密钥或标签，等于没用。
- **先看它是什么身份**：用户密钥、实例角色、联邦令牌，能做的事差很远；实例角色往往权限更大。

## 容器与集群：四种暴露，含金量不同

| 碰到什么 | 意味着 | 值多少 |
|---|---|---|
| 6443 / 8080 上的 API server，且能匿名列资源 | 控制面已有读权限 | 高 |
| kubelet 10250 允许 exec | 能在节点上的容器里执行 | 高 |
| kubelet 只看得到 Pod 与日志 | 只读 | 中：常能捡到令牌与环境变量 |
| etcd 2379 无认证 | 全量集群状态与密钥 | 最高，也说明配置很随意 |
| 编排控制台弱口令 | 图形化控制面 | 高，取决于它绑了多大权限 |
| 只有一个容器里的 shell | 只是容器 | 低，除非能碰宿主 |

**假路**：端口开着但握手被拒、只返回版本号的 403、kubelet 返回 401——这是"能碰到"，不是"进去了"。

## 容器里先看它带着什么身份

容器里最关键的不是提权，是**它被授予了什么**：挂载的令牌、环境变量里的凭据、能访问的集群内地址。
一个服务账号令牌，常常比容器本身的 root 有用。

从容器到节点的判据只有一条：**有没有能影响宿主的挂载或权限**——特权模式、挂载宿主根目录、
挂载容器运行时套接字、能加载内核模块。任何一样成立，容器边界就等于没有；都不成立就走应用层
（令牌、内网服务、构建凭据），别死磕逃逸。

到集群之后先看**权限边界**：能读密钥就是最高一档；只能列 Pod 说明只是观察者；
能改工作负载（部署、镜像、探针）等于能在任意节点起任意容器，等同全集群执行。

## 验证纪律

- **只读不写**。写操作会留审计日志、可能触发告警，也可能真改坏业务。要证明写权限，用"能列出可写目标"
  而不是"真写一个"。
- 云上的横向不是扫端口，是**换身份**：从实例角色换到同账号其它资源、从低权限用户找能承担的角色、
  从能改启动配置的地方拿下一台。这一步一动手就留痕，且厂商审计日志集中、难删。
- 集群里别做清点式操作：一次列出全量资源的动作很显眼，先精确查你要的那个命名空间。

## 收敛与落库

能改配置、改镜像、改密钥，就等于能拿到同账号下的下一台；拿到集群管理权限就收口，
别再为了"更完整"去刷节点。

落库要求：凭据按"能做什么"记（列出 / 读取 / 写入 / 管理），不写"疑似有效"；
桶记名字与权限形态；元数据可达单独记一条成果，它往往是整条链的转折；
"能在某节点执行"和"能控制集群"是两档成果，别混成一条。
