# 主动扫描（判断结果可不可信）

扫描的产出不是端口列表，是**可信的攻击面**。这一步最容易产出假数据：防火墙回包、负载均衡、
蜜罐都会让"开放"变成一个错误结论。

## 判据：什么结果才算真的开放

| 观察 | 含义 | 动作 |
|---|---|---|
| 端口开放且能取到服务 banner | 真开放 | 进指纹与漏洞检测 |
| 端口"开放"但发任何数据都无响应 | 中间设备回包 | 用更大超时与重试复核，不通过就丢弃 |
| 整段每个 IP 的同几个端口都"开放" | 有统一设备在应答 | 整段结果作废，换探测方式 |
| 端口开放但服务版本取不到 | 应用层有限制或非标服务 | 改用应用层探测（直接发该协议请求看回包） |
| 只开放 80/443 且响应头一致 | 前面有统一反代 | 真实攻击面在反代后面的应用，不要继续在端口上耗 |
| 扫描中出现大量超时 | 主机不存在或有速率限制 | 先降速复核，再判断是不是"没有" |

**核心判断**：`nmap` 的 `open` 不等于可访问。只有**能完成一次真实应用层交互**，这个端口才算进入攻击面。

## 什么时候该从"扫"转向"打"

1. 已经拿到足够多的存活目标（能排出优先级）→ 停止扩大范围，开始打；
2. 一段网段扫完只出基础设施设备 → 换网段，不要在同一段上换参数反复扫；
3. 端口全开但服务都定不到产品 → 转应用层探测，不要再堆端口手法；
4. 扫描已经开始触发告警 → 立刻停，改单点定向。

## 扫描方式的取舍

| 手法 | 适用 | 代价 |
|---|---|---|
| 完整 TCP 连接 | 绝大多数场景，最准 | 慢、日志多 |
| 半开扫描 | 需要速度、目标不介意噪声 | 需要高权限，容易被 IDS 记 |
| 无状态高速扫描 | 大网段铺面 | 结果粗糙，需要复核 |
| 应用层探测 | 只开放 Web/数据库端口 | 慢但结论最硬 |

**先粗后细**：大网段先快速过一遍拿存活，只对存活主机做全端口。
对整段做全端口是典型的新手动作——慢、噪声大、还容易被打挂设备。

## 执行位置
互联网目标从本机扫，内网目标先建隧道再从隧道里扫。走隧道时并发要压低，
否则超时表现会被误判成"目标不通"。

## 纪律
- 开扫前锁定扫描网段，并显式排除办公网、工控、打印机等敏感设备；
- 速率从保守值起步，观察目标响应时间再决定是否提高；
- 扫描结果落库时带上**批次信息**（时间、参数、网段），否则后面无法区分"没扫到"和"扫过是空的"。
