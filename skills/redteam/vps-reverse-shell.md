# 公网落地端（三台机器，别搞混）

这个技能涉及三台机器，**每台的命令写法都不同**，判断依据永远是"这条命令在哪台机器上跑"：

| 机器 | 角色 | 命令按什么写 |
|---|---|---|
| 公网落地端（自有服务器） | 收会话、分发载荷、做中转跳板 | 服务器自己的系统 |
| 目标机器 | 反弹、下载载荷、执行 | 目标是什么系统就写什么 |
| 本机 | 登录服务器、上传、取回 | 本机系统（Windows） |

**最常见的错误**是把本机命令写成服务器语法，或把目标侧命令写成自己桌面的语法——
写之前先问一句"这条命令谁来执行"。

## 判据：什么时候必须用公网落地端

| 情形 | 选择 |
|---|---|
| 目标能直连你（同网段、有公网 IP） | **不必**用落地端，直接本机监听 |
| 目标只能出网、你在内网 | 必须用，这是主场景 |
| 目标能出网但只放行 Web 端口 | 用，但监听端口要落在放行的端口上 |
| 只需要跑一两条命令 | **不用**反弹，用已有的 HTTP 通道更稳更隐蔽 |
| 目标完全不出网 | 落地端没用，改走正向转发 |

## 判据：回连不通，问题在哪

| 观察 | 含义 | 动作 |
|---|---|---|
| 目标执行了命令，落地端没收到连接 | 出网被拦 | 换放行的端口；检查目标侧出网策略 |
| 落地端收到连接又立刻断开 | 载荷协议不匹配或被查杀 | 换载荷类型，别重发同一个 |
| 能连上但下发命令无回显 | 会话没有交互能力 | 换交互式载荷，或改用短命令轮询 |
| 第一次通、之后再也不通 | 目标侧有主动防御 | 停止反复触发，改一次性动作 |
| 落地端端口从外部连不上 | 安全组/防火墙没放行 | 先确认端口在服务端真的在监听 |

**核心判断**：回连失败九成是**出网**问题。先确认目标能出哪个端口，再选载荷形态；

## 会话怎么用才不会白拿

1. 上来先确认身份与权限（谁、在哪、能干什么），这是后面所有判断的基础；
2. 命令输出要落文件再取回，不要指望屏幕滚动缓冲；
3. 长期在线的会话要登记，**并写清它是从哪台机器、哪个端口进来的**；
4. 用完就关，不留裸监听——既是资源占用也是痕迹。

## 纪律

- 端口先确认空闲再用，别人的监听不要动；
- 落地端只做落地与中转，**不要在落地端上堆这次演练的业务文件**；
- 目标上抓到的凭据只落本机资产库，**不要写到落地端家目录**；
- 落地端的地址对目标可见，它属于本次演练的基础设施，不要在目标上留下无关个人信息。
