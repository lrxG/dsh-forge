# 控制缺口矩阵与收口（把一个站打透）

**不是把所有接口都扫一遍，是按"端点类型"对每类应有的控制逐条验证它真生效没有。**
这一篇解决两件事：还有哪些面没打，以及什么时候该停。

## 一、端点类型 → 必探控制

| 端点特征 | 应有的控制 | 控制缺失就是 |
|---|---|---|
| 写操作（POST/PUT/DELETE + 资源 id） | 鉴权、所有权、输入完整性、二次确认 | 未授权写、越权改、字段注入 |
| 读单个对象（GET + id） | 认证、所有权、字段级过滤 | 越权读、字段泄露 |
| 导出/批量/下载 | 范围限制、数量限制、鉴权 | 全量或跨租户导出 |
| 角色/权限/授权 | 高级授权、能否自授 | 提权 |
| 资金（转账/支付/退款/优惠券） | 服务端重算、幂等、并发、上限 | 金额篡改、重复使用、透支 |
| 吃 URL / 回调 / 预览 / 导入 | 白名单、协议限制、内网封禁、重定向跟随 | 服务端请求伪造 |
| 文件上传 | 后缀、内容、类型、路径、解析 | 可执行落地 |
| 文件路径类参数（含**删除**） | 路径规范化、前缀校验、协议过滤 | 任意读/任意删 |
| 命令/模板/转换/渲染 | 白名单、拼接符、关键字过滤 | 命令执行 |
| 认证类（登录/重置/验证码/绑定/回调） | 验证码绑定与消费时机、频率、步骤完整、身份字段可控 | 任意登录、接管 |

**删除接口是最高频的盲区**——大多数测试只测了读和写，忘了删。

## 二、拿到新接口先用五发探针（几分钟）

1. 去掉会话重发 → 未授权；
2. 改一个 id（+1 / 换 UUID / 换租户 / 换手机号）→ 越权；
3. 改一个"客户端不该控制"的字段（金额、角色、状态、归属）→ 篡改；
4. 多塞一个页面控件里没有的字段 → 批量赋值；
5. 极端输入（重复参数、null、空数组、超长、数组替字符串）→ 类型混淆与报错泄露。

五发都不出差分，这个接口就当测过，记排除结论，不要反复换 payload。

## 三、九个高频盲区（每次专门过一遍）

文件**删除**接口 · 批量参数 · 导出范围（日期放回十年前、分页拉大）· `OPTIONS`/`HEAD`（拦截器常只管 GET/POST）·
小程序/APP 里有但网页没暴露的接口 · WebSocket/SSE · GraphQL 子字段权限 · 登出与回调的跳转白名单 · 第三方回调无签名。

## 四、同皮与同闸（别把力气耗在重复壳上）

- **同皮**：指纹实质同构（骨架、构建哈希、接口前缀一致）时，族内两三个做全矩阵，其余只做首页与一两个业务口的差分；
- **同闸**：业务接口全是同一句"请登录"、没有条数/长度/耗时差分时，这一片就是一道闸，换面；
- **反例**：回包里有结构、有 `total`、报错不同、长度或耗时明显不同——那是有差分面，必须测。
- 同 host 不同 path 一律展开，不要因为"页面长得一样"跳过。

## 五、蜜罐：轻量核查，不为它停工

目标像蜜罐时**不当结论用**，只做一次浅层核查：多个不同服务是否共用同一套响应头与错误页、
页面引用的资源是否全 404、正文是否留着占位符、我前几发是否被它自己记录。
**"版本老、暴露全、看起来太诱人"不是蜜罐证据**，那正是真实系统的常态。
只有命中明确的仿真器特征才停下问用户；判不出就照常打。

## 六、收口判据（达到即换面）

1. 已写清这摊是什么（或确认抽不出业务对象，记空壳）；
2. 接口清单已建，钥匙类线索抽过，没有就写"无"；
3. 控制矩阵按端点类型勾完，没入口的记 N/A 并写原因；
4. 五发探针在**有差分面**的参数上打穿或证伪；
5. 认证类入口勾完；
6. 有会话时对象图、换 id、加字段、跳步都打了；
7. 高价值苗头（稳定注入、能串成链、跨租户、未授权敏感读、可用凭据、进号）**先打穿再换面**；
8. 结果归档进报告。

## 七、空转信号（命中就换面，不是去扩面）

长时间没有新发现只有 403/健康检查/重复路径 · 在瘦壳上开全矩阵 · 同一道闸上反复试 payload ·
为凑对照号去磨注册或验证码 · 把已经记录过的结论再确认一遍。

**算进度**：清单推进、差分真的发出去过、回包线索进了待打队列、报告新增、未登录例外打穿或证伪。
**不算进度**：接口条数、探活数量、喷了多少个引号。

## 执行位置
本机经代理；内网目标先隧道。同皮批量只在已确认的范围内。

## 落库
每个测过的端点写 `redteam_asset_test` 的 test 字段（追加），把"测了什么、结论是什么"留下；
排除结论必须写清原因，否则下一个人会重测一遍。
