# 测绘平台扩面（找得最全，但最容易浪费配额）

## 凭据
API Key 从环境变量 `FOFA_KEY` 读，**任何 key 都不要写进仓库、报告、命令原文**。

## 判据：这一路值不值得继续

| 信号 | 含义 | 动作 |
|---|---|---|
| `cert="域名"` 命中同证书的多条记录 | 证书里带 SAN，能一次拉出同证书下的其它域名，**是扩面命中率最高的一条** | 优先跑这条，再按结果逐个下钻 |
| `org="单位名"` 命中但域名和时间段都很散 | 单位名下多个业务系统，值得全收 | 按域名分组，逐组建资产 |
| 返回条数上万且标题高度雷同 | 查询语句太宽（纯 `body=` / `title=`），拿到的都是噪声 | 立刻收紧，叠加域名或 IP 段限定 |
| 同一 IP 上挂着大量无关站点 | 共享主机/CDN，打它不属于目标 | 排除，别入资产库 |
| 返回 `[-700] 账号无效` | key 本身不可用，不是限速 | 转被动源（crt.sh / 被动 DNS / subfinder）继续铺面，并把 key 失效一并告诉操作者；不在这条上重试 |
| 返回 `[45012] 请求速度过快` | 触发限速 | 退避后再来，绝不并发狂刷 |

**换路条件**：测绘结果与证书透明、被动 DNS 给不出交集时，说明该单位在测绘平台上的数据不全，
转被动源与备案信息，不要在测绘平台上反复换语法硬凑。

## 查询构造思路（比具体语法重要）

1. **从最确定的字段开始**：证书 → 域名 → 组织名 → IP 段，越往后越宽；
2. **每一次查询都要能回答"它能排除什么"**：不缩小范围的查询等于没查；
3. **组合优先于单条件**：单用 `title="登录"` 全互联网都是后台，加上 `domain=` 才有意义；
4. **按端口查只在你已知该服务暴露时用**：`port="6379"` 之类的语句会立刻把结果推到几十万条。

## 配额与限速（必须守住）

- 官方限速是**每秒 1 次**（低档套餐），按 1 请求/秒保守执行，**绝不并发**；
- 单次任务设请求上限（几十次就够），打满就停，不要"再多翻一页"；
- 同一查询结果先落盘缓存，重跑前先看有没有现成结果；
- 配额耗尽时换被动源，不要在一个平台上反复试探。

## 执行位置
本机。查询请求走代理，不要把本机出口暴露给第三方平台。

## 落库
结果按批量方式入资产库，来源标 `passive`；域名进 `names`、标题与服务器头进对应字段。
测绘拿到的资产后面一定要**用主动探测确认存活**再进扫描队列——测绘平台上大量条目早已下线。
