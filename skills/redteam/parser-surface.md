# 解析器入口面（输入到底进没进解析器）

SSRF、XXE、反序列化、模板注入是四件事，判断链是同一条：**可控 → 真的进了解析器 → 有我能观测到的反馈**。
断在任何一环，都只能记候选，不能记成果。

## 共用判据

| 环节 | 成立 | 只是像 |
|---|---|---|
| 可控 | 我改的值改变了服务端行为（回显、耗时、状态码、外带请求） | 我的字符串出现在页面里 |
| 进了解析器 | 报错里出现解析器/类的名字，或畸形输入让行为分叉 | 接口接受字段但忽略它 |
| 有反馈 | 拿到目标侧的内容、时间差稳定复现、外带通道收到带我自己标识的请求 | 只是 DNS 解析、只是连通、只是 200 |

**随机串是最便宜的证据**：注入只有我能生成的串，看它是否出现在目标侧的响应或外带里。
出现 = 真处理；不出现 = 至少这一层没经手。

## SSRF

- 只有"能发请求"不算，要能读到响应内容才算完整 SSRF；读不到就降级为盲打，走外带通道判。
- 探测顺序：本机回环 → 内网管理口 → 云元数据地址 → 非常规协议。每一层用**只有该层才有的响应特征**判，不要只看连不连得上。
- 过滤常见于正则黑名单与协议白名单：换编码、换重定向、换解析差异（`@`、短域名、大小写、DNS 重绑定）比硬怼关键字更有用。
- 云上目标的判据是**能不能拿回凭据**，不是"能不能访问元数据地址"；拿到凭据立即验证权限，验不了就只记一条。
- 反例：只回显自己的请求头、只能打到自己控制的域名、只能 DNS 出网——都算半条。

## XXE

- 前提是**这个接口真的按 XML 解析**：JSON 接口常留 XML 兼容，试一次带实体的最小文档即可判定。
- 判据分三档：报错里回显文件内容（完整）→ 外带（盲打）→ 只有解析耗时变化（弱信号）。
- 外部实体被关掉时通常**静默成功**，不要因为"没报错"就认为不可用。
- 参数实体、编码实体、XInclude 是三个不同入口，一个关了不等于都关。

## 反序列化

- 先确认字节流真被反序列化：改一个字节，看行为是否分叉（报错类名、状态码、耗时）。
- 黑盒看不到类路径时，判据是**可控字段能否改变对象语义**（长度、类型、引用），而不是"有没有报错"。
- 入口信号：序列化后的 cookie、隐藏表单、`viewstate`、二进制 body、magic 头（`rO0`、`AC ED`、`H4sI`）。
- 有链才有洞。找不到链时记录"存在反序列化点"，这是资产不是成果。

## 模板注入

- 判据是**表达式被求值**：算一个只有服务端才会算的数，看结果是否回显。
- 只回显字符串 = 渲染，不是注入；能算术但不能调用 = 沙箱模板，继续找逃逸点或停。
- 客户端模板（浏览器里渲染）属于前端面，见 `browser-surface`，不要写成服务端注入。

## 换路条件

- 参数、请求头、文件内容三处都无差分 → 这个入口不是解析面，换入口；
- 有 DNS 出网但拿不到 HTTP 响应 → 出网被限，转外带通道或换协议；
- 只能触发报错、改不了语义 → 记为"存在解析点"，不再往下钻；
- 三种编码绕过都被同一规则拦 → 大概率是白名单，转别的面。

## 落库

每条必须附**原始请求 + 目标侧响应原文**；盲打类把外带记录时间与标识写进证据。
SSRF 拿不到内容时严重级按信息泄露算，不要按 RCE 写；反序列化没有链按"可利用前置条件"记候选。
