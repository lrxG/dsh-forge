# 子域枚举与初筛（高频：每个外网目标都要走一遍）

这一步的产物不是"一堆域名"，是**三条队列**：值得看、需要接管验证、直接丢弃。
枚举做得全不难，难在判出哪些结果根本不能用。

## 三条判据决定枚举是否有效

| 现象 | 含义 | 该做什么 |
|---|---|---|
| 随机生成的子域也能解析 | 泛解析 | DNS 爆破全部失效，转证书透明与被动 DNS |
| 两轮不同来源都不再新增 | 面已铺到 | 停止枚举，不要换源硬凑 |
| 同证书覆盖多个域名 | 最可靠的扩面来源 | 拿证书维度继续扩，比字典准 |
| 存活率极低、全部指向同一批边缘 IP | CDN 或出口问题 | 先修链路，再扩面 |

## 三条队列怎么分

1. **值得看**：解析到真实业务 IP、有独立证书、响应头不像 CDN 通用页。
2. **需要接管验证**：CNAME 指向第三方托管平台（对象存储、静态托管、PaaS、商店后台）。
   → 交给 `subdomain-takeover`，**这一步不做判定**。
3. **直接丢弃**：泛解析回包、CDN 边缘通用页、通配符指向的同一批节点。

**判据**：队列 2 的唯一入口条件是"CNAME 指向第三方"，不是"响应看起来像报错"。
报错页每天都能看到几千个，全都不是候选。

## 命中率决定打法（重要）

实测某次 494 个通配符域全量枚举：候选 31 万余、解析成功 15 万、带 CNAME 6.4 万、
平台候选 1.3 万、**真正成立 4 条**——命中率约 0.006%。

结论只有一条：**不可能靠"挑对目标"提高命中，只能靠铺得够宽**。
选目标只用于排除（无资产、测不了、红海），不要指望精挑细选能提高转化。
同批 1.3 万条 CloudFront 候选全是通用 403，一次过滤掉，不要逐条人看。

## 换路条件

- 连续两个数据源无新增 → 停；
- 只剩 CDN 边缘与泛解析 → 这一面结束，转其他资产；
- 目标是单点系统、没有子域面 → 不要为了凑数去跑字典。

## 落库

资产入库存 **CNAME 链与解析来源**（证书/被动/字典），这是后面判接管的前提；
进入队列 2 的候选标成待验证状态，不要直接记漏洞。枚举数量与去重后数量一起记，方便收口对账。
