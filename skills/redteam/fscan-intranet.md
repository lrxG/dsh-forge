# 内网扫描（先铺面，再定向）

扫描给的是**一张能排序的图**：哪些网段真的活着、服务能不能定到产品、有没有弱口令与未授权。
它不证明"扫完了"，也不证明"没洞"。代价是噪声大、容易打崩老设备。

## 铺面与定向是两件事

| 情形 | 做法 |
|---|---|
| /16、/12 这种大网段，不知道哪几段在用 | 先探点再发散，发包可控 |
| 已知几台目标，要快速找弱口令与未授权 | 直接对存活主机做定向动作 |
| 已有一个具体服务要深入打 | 转对应技能，别为了顺手再全量跑一遍 |

**全端口只对已确认存活且值得打的单机做**，大网段上全端口等于自报行踪。
先全量跑不只是慢：会在不存在的主机上浪费时间，还会提前惊动防守。

## 结果不可信的形状

| 信号 | 含义 | 动作 |
|---|---|---|
| 大量主机"全端口开放" | 中间有设备对所有端口回 SYN-ACK | 放大超时重试复核，别当真实开放 |
| 同网段每台都开放同样几个端口 | 设备统一回包 | 判为假开放，换探测方式 |
| 前期命中很多、后期几乎没有 | 前面打的是网关与基础设施 | 换探点网段，扩大发散 |
| 指纹只到"是 HTTP 服务" | 强度不够 | 看这台在不在核心网段，再决定加深还是放弃 |
| 同一主机上大量不搭的服务、响应极其规整 | 大概率蜜罐 | 标记跳过，不在其上做任何利用 |

## 该收手的信号

| 信号 | 动作 |
|---|---|
| 目标侧响应时间明显上升 | 降线程/限速，老设备会被打挂 |
| 弱口令尝试中出现账号锁定告警 | 停对这个账号的尝试，换账号或换协议 |
| 连续两台设备在扫描中掉线 | 全停，报告，等明确指令 |
| 开始集中告警 | 停，改单点定向手法 |

第一轮只拿资产面，不爆破不开 POC；第二轮才定向。域账号尤其危险：锁一次可能毁掉整条横向路径。

**显式排除**：办公网段、打印机、工控设备、云元数据地址。打错就是事故。

## 走隧道时

隧道本身是瓶颈：并发压低、超时放大。判法很简单——先对一台已知可达的内网主机单发几个包，
通就不是网络问题，是并发太高；不通再谈目标有没有东西。

## 结果落库

存活主机、开放服务、凭据与访问、确认的未授权分别落库；扫描批次要能说清用了什么参数、扫了哪个网段、
什么时候，否则后面分不清"测过没问题"和"根本没扫到"。

关键信息（证书、JWT、邮箱、明文口令）单独落库——这类常常比端口本身值钱。
打到一台有指纹的主机，先想"它能通向哪里"，而不是"还能在它身上扫出什么"。
