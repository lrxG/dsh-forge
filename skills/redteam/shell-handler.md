# 反弹会话与载荷投递（判断能不能回连）

**命令执行不等于会话**。一次性的命令回显只能证明有洞，不能持续操作。
本技能判断的是：要不要花代价把它变成会话，以及回连不通时该换什么。

## 判据：值不值得建会话

| 情形 | 选择 |
|---|---|
| 只需要跑一两条命令确认漏洞存在 | **不建会话**，用完即走，留的痕迹最少 |
| 需要传文件、开隧道、长时间操作 | 建会话，但优先建成"能复用给用户的入口"（加密马） |
| 目标只能出 HTTP，命令行通道够用 | 用 HTTP 通道反复投递，不必非要一个交互 shell |
| 目标出网被严格限制 | 会话很可能建不起来，先评估可行性再动手 |
| 已经有 WebShell 但操作不便 | 不必转反弹，直接从 WebShell 进隧道 |

## 判据：回连不通，问题在哪一层

| 观察 | 含义 | 换什么 |
|---|---|---|
| 目标执行了命令但你的监听没收到连接 | 目标出网被拦 | 试 Web 端口出网；不行就改用 HTTP 通道投递 |
| 收到连接但立刻断开 | 载荷与监听协议不匹配，或目标侧有杀软 | 换协议（换端口/换载荷类型），别重发同一个 |
| 连上了但没有回显 | shell 没有 TTY 或标准输入输出没绑定 | 换交互式载荷，或直接改用命令回显模式 |
| 第一次通、再触发就不通 | 目标侧有主动防御或连接数限制 | 降低频率，改一次性动作 |
| 命令被截断、特殊字符失效 | 注入点做了过滤 | 整体编码后再传，不要逐字符绕 |

**核心判断**：回连失败九成是**出网**问题，不是载荷问题。先确认目标能出哪个端口，再选载荷形态。

## 会话稳定与权限

裸会话通常没有交互能力（不能 `su`、不能开编辑器），需要升级才能做提权类操作。
但升级本身也带来更多流量特征——**只在真的要提权时才升级**。

会话拿到的权限要如实记录：普通用户、服务账户、管理员、SYSTEM 是四个完全不同的结论，
报告里写错一级就会让整条攻击链的判断失真。

## 载荷投递的取舍

1. **一次性下载**：目标能出 HTTP 时最稳，用完文件即删；
2. **长期落地**：目标需要反复用工具时才落盘，落盘就要考虑清理；
3. **投递位置**：临时目录、可写目录，且文件名不要有特征；
4. **投递失败**：换协议（HTTP→HTTPS）、换拉取方式，不要反复试同一个 URL。

## 执行位置（最容易搞错的一点）

这个技能涉及三台机器，命令写法完全不同：

- **你的服务器**（公网落地端）：开放监听、接收会话、分发载荷——它通常是 Linux，命令按它写；
- **目标机器**：反弹命令、下载载荷、执行——目标是什么系统就写什么命令；
- **你的本机**：只做登录、上传、取回——本机是 Windows，命令按本机 shell 写。

判断依据是"这条命令在哪台机器上跑"，不是"这段内容属于哪个技能"。
写混了就会出现在 Windows 上执行 `bash`、或在 Linux 上用 PowerShell 语法的情况。

## 纪律
- 监听端口避开目标所在环境已占用的端口段，先确认占用；
- 会话要能重连，但不要为了重连反复触发（每次触发都是一次日志）；
- 交付给用户优先用加密马，临时会话要说明"一次性，不是交付入口"；
- 落地文件、监听的进程用完清理。
