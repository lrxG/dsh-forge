# 签名与对象存储（什么才算拿到钥匙）

这一类最容易把"看起来像"当成"拿到了"：看到 AK/SK、看到预签 URL、看到 STS 就写成果，结果一打全是占位或已失效。
**只有能签出、能列出、能覆盖别人的对象，才算。**

## 判据：钥匙是真的还是占位

| 观察 | 结论 | 动作 |
|---|---|---|
| 用这把钥匙调接口返回"身份/账号信息" | 真钥匙 | 记录能力范围（能列谁的对象、能写哪里） |
| 返回"签名不匹配/无效" | 占位或已轮换 | 换下一把，不要反复调 |
| 只能访问公开读的桶/目录 | 公开配置，不是洞 | 记一行排除结论 |
| 能列出**别人前缀**的对象 | 真越权 | 取一个对象证实内容真实存在 |
| 能覆盖/删除别人已引用的对象 | 真写权限（危害最高） | 只在一个无害对象上验证，立即恢复 |
| 预签 URL 的签名没罩住 host | 可以把域名换成同账号别的桶 | 换成另一个桶验证能否读到别的对象 |
| 隐藏路径返回策略 JSON 且全是 Allow | 桶策略放开 | 先只读列举，写操作只试一次 |

**核心标准：能证明"这是别人的数据"或"我改变了别人的数据"**。只有密钥字符串、只有 200、只有"策略看起来是全 Allow"都不算。

## 找钥匙的几个地方（按命中率）

1. 打包 JS 与其异步 chunk、sourcemap 里写死的密钥、盐、演示账号、公钥；
2. 文档/Demo 包/接入示例/历史版本的包里明文写死的密钥（同一套东西常有多处）；
3. 领临时凭证的接口——它本身可能就是未登录的；
4. 上传前的"取签名"接口：如果签名在前端算，盐就在前端；
5. 报错信息里拼出来的 URL（常带 token 或 secret）；
6. 网关代理出来的存储签名接口，参数直接就是对象 key。

## 换路条件

- 三把钥匙都调不通 → 停止找钥匙，转泄露链（配置文件、备份、源码里的连接串）；
- 桶只能读公开内容 → 记排除结论，转别的面，不要继续枚举；
- 预签 URL 的签名罩住了 host 且有效期很短 → 这条不通，转对象越权（技能 `object-and-tenant`）；
- 上传点能写但内容类型被卡死 → 先确认是否还有另一条取签名路径，没有就停。

## 边界

只读优先；写操作只验一次，且选不影响业务的对象，验完恢复。
不要覆盖官方文档、协议、首页图这类被引用的对象——那是破坏，不是成果。
列出他人数据时只统计条数与类型，不要把内容整体拖回来。

## 执行位置
本机经代理。走隧道时降并发——存储类接口容易被限速，超时会被误判成"没权限"。

## 落库
钥匙记凭据条目（写清来源位置、能力范围、是否已验证）；越权读写记漏洞条目并附原始请求；
**不要把密钥原文写进报告正文**，落库即可。
