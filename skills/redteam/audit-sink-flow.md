# Sink 与数据流（四段全通才算）

代码审计的误报几乎都来自一个动作：**看到危险函数就下结论**。
看到字符串拼接不等于 SQL 注入，看到反序列化不等于 RCE——中间隔着三段，任何一段断了都不成立。

四段：**source 外部可控 → 传播无有效净化 → sink 真的危险 → 入口真的可达**。
少一段只能记候选，并在证据里写清缺哪一段。

## 一、source：谁能控制它

| 来源 | 算外部可控 | 注意 |
|---|---|---|
| 请求参数、头、cookie、body、路径段 | 是 | 包括框架自动绑定的对象字段 |
| 上传文件名、解压后的路径、压缩包内条目 | 是 | 常被当成"内部数据"放过 |
| 数据库里别的用户写过的内容 | 是（二阶） | 二次注入就靠它，别当可信数据 |
| 上游服务/消息体/配置中心 | 看谁能写 | 能被普通用户间接写入就算可控 |
| 常量、枚举、服务端生成的 id | 否 | 除非能证明它由外部拼接而成 |
| 前端校验过的字段 | **是** | 前端校验不改变可控性 |

**判据**：能不能用一句话写出"这个值由谁在什么时候决定"。写不出来就去找调用方，
找不到调用方的，按不可控记，不要猜。

## 二、传播：净化是不是真有效

- **编码不改变可控性**：URL 编码、Base64、JSON 序列化只是换形态，解开之后还是可控。
- **转义只在对应上下文有效**：HTML 转义治不了 SQL；SQL 的 `addslashes` 治不了数字型注入；
  路径的 `..` 过滤用字符串替换可被双写绕过。
- **类型转换能截断但不能算净化**：`parseInt` 会让字符串变数字，但如果它进的是拼接 SQL 的数字位置，仍要确认没有被二次拼回。
- **白名单是唯一可靠的净化**：映射表、枚举校验、正则全匹配（不是包含）。黑名单不算。
- **框架自带能力要确认真的用了**：ORM 的 `where` 参数化是安全的，但同一个 ORM 里 `raw`、`order by`、表名拼接仍是拼接。

## 三、sink：只记容易判错的地方

可控值进未参数化的语句、进 shell 字符串、进 `eval` 这类通用判据不必写。下面只记容易判错的：

| 类别 | 容易判错的一点 |
|---|---|
| SQL | `order by`、表名、`like` 处的拼接同样成立；同一个 ORM 里 `raw` 与动态表名也是拼接 |
| 文件 | 判据不是"过滤了 `..`"，而是 realpath 之后做前缀比较；`normalize` 后没比较等于没做 |
| 上传 | 后缀可绕只是必要条件，还要看落地目录能不能执行、是否落到对象存储 |
| 反序列化 | 可控字节 + 类路径上有可用 gadget 才成立；有类白名单或过滤器就是死的 |
| 模板 | 可控的是**模板内容**才成立；固定模板渲染用户数据不是 |
| SSRF | 看请求库是否跟随重定向，以及是不是只做了黑名单 |
| 代码/表达式 | 沙箱能逃才成立；有类型白名单与调用限制的不算 |
| 日志/CRLF | 一般不算，除非能进下游解析或响应拆分 |

## 四、可达性：这条路径真的会走到

- 路由是否注册、是否被注释、是否只在某个 profile 下启用；
- feature flag / 配置开关默认值；
- 鉴权是否在前面拦住（与 `audit-surface` 的矩阵对照）；
- 版本：修过的版本要看当前分支代码，不要拿老版本结论。

## 反例（我踩过的）

- 看到 `StringBuilder` 拼 SQL 就报注入——最后发现那个方法只用于内部报表拼接固定列名。
- 看到 `ObjectInputStream` 就报 RCE——项目全局配置了类白名单，且没有可用 gadget。
- 看到"过滤了 `../`"就报穿越——后端做了 `realpath` 前缀比较，过滤是双保险。
- 看到上传只校验后缀就报 getshell——文件落在对象存储，不进 Web 根。

**共性**：三段里我只看了第一段（可控）和第三段（危险函数），跳过了传播与可达性。

## 换路条件

- source 不可控 → 换调用方，或记"内部数据"结案；
- 传播有白名单/参数化 → 这条路死，去同一个 sink 的其他调用点；
- sink 危险但入口不可达（未注册路由、开关关闭）→ 记资产状态，不记漏洞；
- 反序列化点找不到 gadget → 记"存在反序列化入口"，等有链再升级。

## 落库

每条证据写：**source 位置（谁可控）→ 传播路径（函数链）→ sink 位置（文件行）→ 可达性（路由/鉴权）**。
四段有缺的写清缺哪段，严重级按已证到的最后一段给，不要按想象的最坏情况给。
白盒找到的点要用黑盒复核一次（`exec-surface` / `object-and-tenant`），两边能对上才算成立。
