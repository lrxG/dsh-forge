# 凭据攻击（判断哪条路值得试）

拿账号权限最稳的两条路：**配置或源码里拿到明文**，以及**口令本身太弱**。
本技能只管后者，而且重点是判断"该在什么时候停"。

## 判据：什么算拿到账号权限

**只有凭据不算。** 必须在真实浏览器里登进去、看到后台或能操作，才算成立。
登不进去的凭据只是线索，落库时标清卡在哪一步（需二次认证、限制来源 IP、账号已禁用、口令已过期）。

## 在线试口令：什么时候做、什么时候必须停

| 信号 | 含义 | 动作 |
|---|---|---|
| 用产品默认口令一次命中 | 目标从未改过默认配置 | 立即停手并登录验证，不要再跑字典 |
| 试了十来次后响应变慢或出现提示"账号已锁定" | 触发锁定策略 | **立刻停**，换账号或换目标；锁一次可能毁掉整条路径 |
| 用户名对了但口令永远错，且报错信息不区分用户是否存在 | 有防枚举设计 | 不要靠报错区分账号，改用默认口令与泄露库 |
| 同一口令在多台主机上都能用 | 口令复用 | 这是内网横向里命中率最高的一招，优先级高于继续爆破 |
| 目标出现验证码或滑块 | 这不是爆破能过的东西 | 不要硬爆，转别的入口 |
| 连续几次都是 429/403 | 已经被封 | 判断是封 IP 还是封行为，降频优先于换 IP |

**判断优先级**：默认口令 → 已知泄露凭据 → 针对性小字典 → 通用大字典。
体量上，针对性字典（单位名、品牌、年份组合）命中率远高于通用大字典，且噪声小得多。

## 在线试口令的期望值

- **互联网单点**：除产品默认口令与已知泄露凭据外，在线尝试基本靠运气，而每次尝试都在积累告警；
  成功率与尝试量不成正比。
- **内网同镜像批量**：默认口令与同口令复用的命中率高，在线爆破真正划算的场景在这里。
- **能用，不是禁区**：看不出是什么系统、又只有这一个入口时，试一轮默认口令+小字典是合理的；
  期望值低的是「不知道是什么、先拿大字典跑一遍」。判断依据是手上有没有理由，不是动作本身。
- 单入口百条量级没有结果，说明口令强度高于字典覆盖——换目标比加字典更值。

**字典是增量资产**：平时遇到的新口令习惯、单位词、年份组合、产品默认口令，随手记进字典；
维护以新增为主，旧字典只做去重与补充，不要每次重建。

## 离线破解：值不值得挂时间

离线破解不产生目标侧流量，但它消耗的是你自己的时间：

| 信号 | 含义 | 动作 |
|---|---|---|
| 哈希类型是快速的（MD5/NTLM）且字典里能命中 | 值得跑 | 跑字典 + 规则即可结束 |
| 慢哈希（bcrypt 等）且没有 GPU | 单条可能几十分钟 | 只跑针对性字典，跑不出来就停 |
| 已经拿到哈希且能直接复用 | 根本不需要破解 | 直接拿去打（哈希传递），离线破解是最后一步 |
| 跑了两轮字典零命中 | 口令强度高于字典覆盖 | 停，转向其他路径 |

**核心判断**：破解的目的通常是复用这个账号，而**复用不需要明文**。所以离线破解的优先级
永远低于"直接把哈希打出去"。

## 凭据复用（最容易被忽略的高价值动作）

拿到任何一组凭据后，先横向试，而不是急着攻下一个点：
1. 同一口令试其它主机与其它协议；
2. 本地管理员口令复用（同镜像批量装机的机器常同口令）；
3. 域账号试域内共享、OA、邮件、堡垒机、运维平台；
4. 用户名规律（姓名、工号、邮箱前缀）配合已知口令试同系统其它账号。

## 执行位置
试口令在**能直达目标的位置**执行：互联网目标从本机，内网目标先建隧道再从隧道里打。
爆破流量本身也要走代理，不要把本机出口暴露给目标。

## 纪律
- 先查库，别重复爆同一个入口；被标成 abandoned 的资产不要再碰；
- 字典不超过百条量级，命中即停；没有结果换目标，不加字典续命；
- 明文口令落库，但**不要写进报告正文与对话**；
- 内网批量弱口令交给内网普查技能，本技能用于单点精细控制。
