# 模板化漏洞检测（判断命中可不可信）

模板库覆盖面很广：CVE、暴露面、错误配置、默认口令、未授权访问。它的强项是**快**，
弱项是**容易命中假阳性**，而且一次全量轰的火力足以打挂小站。

## 判据：什么算真命中

| 观察 | 结论 | 动作 |
|---|---|---|
| 模板的 matched-at 里带**版本号以外的实证**（回显内容、命令输出、报错细节） | 真命中 | 存原始响应作为证据 |
| 只匹配到版本号或标题 | **不算** | 必须手工复现一次才能记 |
| 命中后立即复测，结果变了 | 缓存、CDN 或边缘节点 | 换会话重测，两次一致才算 |
| 同一个模板在一批站点上全部命中 | 模板阈值太宽 | 抽两三个手工复现，确认后再采用 |
| 命中 `dos`、`fuzz`、`bruteforce` 类标签 | 会打挂目标 | 这类标签应当被排除，不要为了"查得更全"放开 |

**核心判断**：模板命中只是**线索**，漏洞成立的标准是**能被复现**。
报告里写的每一条，都要能拿着命令再打一次。

## 什么时候该换模板组

| 信号 | 含义 | 动作 |
|---|---|---|
| 一轮跑完零命中 | 目标不在模板覆盖范围，或防护拦掉了 | 换思路：看暴露面与逻辑漏洞，别换模板组继续轰 |
| 命中一堆低危（信息泄露、版本披露） | 与得分无关 | 记一行排除结论，不要深挖 |
| 单目标被拦（大量 403/429） | 已经被封 | 降速或换出口；同一目标被封多次就放弃 |
| 目标在 5 分钟内响应明显变慢 | 火力过猛 | 立刻降并发，宁可慢 |
| 已确认一条高危 | 这台的结论已定 | 停止对它的全量扫描，转去打这条链 |

## 这类动作的收益结构

- **互联网**：模板检测的价值几乎全部来自「已经知道它是什么」或「暴露面本身有意义」。
  对不明资产全量过模板，命中率低，而成本是实的——告警、封 IP、WAF 记录，火力大了还会打挂小站。
- **内网**：段小、组件同质、防护弱，模板与弱口令的期望值在这里最高。
- **能用，不是禁区**：能说出「它大概率是什么、为什么值得打」，或者判断这次大概率能出货，就打；
  说不出理由、只是「扫一遍看看」时，同样的时间放在暴露面与逻辑面上收益更高。

## 模板是增量资产

漏洞是增量的：新披露的 CVE、新的指纹、新的暴露面每天都在加。所以模板库的维护以**新增**为主，
旧条目只在新版本或新利用条件出现时修正；覆盖式重刷、整库重建没有意义，还会丢掉本机已有的本地化改动。

## 模板选择思路

1. **有指纹线索时按组件选模板**，比全量轰命中率高、噪声小一个数量级；
2. **先高危后低危**：先只跑严重与高危，命中后再决定要不要往下钻；
3. **批量场景先筛存活**：拿死链去跑模板只会浪费时间和配额；
4. **生产系统避开业务高峰**，会触发重建、同步、索引的模板先在测试资产上验证。

## 执行位置
互联网目标从本机跑，内网目标先建隧道再从隧道里跑。走隧道时并发压到很低——
隧道拥塞造成的失败会被误读成"目标没漏洞"。

内网目标还要注意：隧道只代理 TCP，部分模板走非 TCP 协议时不适用，要改用端口映射。

## 纪律
- 排除危险标签这一点不要动，打挂了生产系统等于毁掉整次演练；
- 被拦先降速再加代理，换 IP 不是第一选择；
- 命中后立刻落库带证据；
- 与得分无关的发现最多记一行排除结论，不要把时间花在它们身上。
