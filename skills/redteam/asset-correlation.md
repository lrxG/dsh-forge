# 资产关联（判断归属，不是画图）

关联的唯一目的是回答两个问题：**这个资产打下来算不算得分**、**从这里能顺着走到哪里**。
能连成一片的资产才有横向价值；连错的边会让后面的判定全错。

## 判据：什么关系才算真的连上了

| 关系 | 成立条件 | 不成立 / 可疑的信号 |
|---|---|---|
| 域名 → IP | 解析记录稳定，且多次解析一致 | 同一域名解析结果在多个无关 IP 之间跳（CDN），这层关系对攻击无意义 |
| IP → C 段 | IP 归属与路由确认过 | 只是"看着像同一段"，云厂商共享段经常混着不同租户 |
| 证书共享 | 同一张证书的 SAN 里同时出现两个域名 | 同一 CA、同一有效期但不同证书，不算共享，只能算同批签发 |
| 端口 → 资产 | 端口在该 IP 上确实开放且服务可识别 | 中间设备对所有端口回 SYN-ACK（全端口"全开"），这层关系是假的 |
| 同一主体 | 备案、组织名、证书主体任两条能互相印证 | 只有标题相似或页面模板相似，**不足以下归属结论** |

## 关联出来的东西怎么用

1. **能连成片的**：从已拿下的主机顺着"内网可达 + 同凭据可复用"扩出去，这是横向的起点；
2. **只是看起来像的**：单独标记，**不进横向路径**，打下来按独立资产算；
3. **证书共享指向的域名**：很多未备案系统藏在这里，值得单独排优先级；
4. **同一 C 段里的不同目标**：注意边界——不属于本次授权的资产不能碰，即便技术上可达。

## 什么时候该停

- 再往外连已经需要"猜"（没有解析、没有证书、没有备案印证）→ 停止扩，标记为待确认；
- 图谱里出现一个连接了所有资产的"超级节点"（比如一台公网反代）→ 它通常是入口而不是目标，
  先打这一台的价值高于继续铺边。

## 落库
关系是幂等的，重复写不产生重复边。**误连的边比漏连更糟**：漏了只是没发现，连错了会让后面
把不属于目标的资产当成靶标。拿不准时标成待确认，不要直接连。
