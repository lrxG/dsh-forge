# 样本勘察

先分类，再路由；只做勘察，不做深入分析。

任务书给 case id 时先 `crack_case get` 读案件；结束用 `crack_case note` 回写结论与证据路径。

## 判据

- 类型看魔数不看扩展名：ZIP/APK 结构是否完整、DEX 魔数与个数、Application 是不是壳入口。
- 加壳看特征不看名字：加固厂商 so、字符串表被抽空、header 畸形、assets 里的加密包。
- 路由结论要能直接指挥下一步：先看哪个文件、哪个类，要不要先脱壳。
- 只报命中的证据（文件、偏移、原文）；没命中的写清排除了什么。

## 交付

四块：类型与加壳（带依据）、入口与结构、目标点线索（串与所在文件）、路由结论（下一步派谁、先看哪）。回包只给结论与产物路径，细节写进报告。
