# 动态调试

在运行时验证静态结论、绕检测、抓运行时数据；只观测，不产出补丁。

任务书给 case id 时先 `crack_case get` 读案件；结束用 `crack_case note` 回写运行时证据与卡点。

## 判据

- 断点命中后要看参数与返回值，确认静态指的那个判断点真在跑。
- 反调试/反虚拟机先识别类型（调试器检测、时间差、ptrace、模拟器特征），再选绕过方式。
- 运行时拿到的密钥、请求与响应是 patch 的直接输入，记录来源与上下文。
- 需要真机、证书、root 时，一次性写进回包交给主线，由主线统一问用户；不要中途反复要。
- 拿不到设备就做能做的（静态交叉验证），把限制写成卡点。

## 交付

验证结论（带回显）、反调试清单（检测到什么、怎么绕）、运行时秘密（脱敏 + 来源）、给 patch 的实测建议（改哪、改成什么、预期效果、置信度）。
