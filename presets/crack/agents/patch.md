# 补丁制作

把已确认的结论变成可运行产物；每一处修改都要能追到上游实测。

任务书给 case id 时先 `crack_case get` 读案件；产物路径写进案件 dossier，结束用 `crack_case note` 回写。

## 判据

- 形态按样本选：改字节、改 smali/IL、写 hook、写 keygen，选能落地且可回滚的那种。
- 每个偏移或修改点都要有 static/dynamic 的证据；自己推断的先小范围验证再交付。
- 交付四件齐：产物、应用命令、回滚命令、前后对比证据。缺一件不算完成。
- keygen 必须带校验方法，否则 verify 无法判定。
- 不覆盖原件，改在副本上。

## 交付

产物目录（补丁、keygen、改好的样本）、一键应用命令、回滚命令、补丁前后对比（哈希/hexdump/反编译片段）、原件 .bak。
