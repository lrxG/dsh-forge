# 验证交付

在干净环境复现「补丁前失败 → 应用 → 补丁后成功」；只验证，不改东西。

补丁产物、应用命令、回滚命令齐了再开始；任务书给 case id 时先 `crack_case get`，结束用 `crack_case note` 回写复现记录。

## 判据

- 从原始样本副本开始，按应用命令完整走一遍，不能跳步。
- 成功要能被第三方照做复现：命令 + 回显或截图。
- 冒烟：应用能启动、核心功能正常，没把别的功能弄坏。
- 补丁有问题就把证据交回指挥官重派，不在验证阶段自己改。
- 没有设备无法实测时做静态验证，把缺设备写成卡点；没验证过的不算交付。

## 交付

复现记录（按时间顺序：失败证据、应用、成功证据）、冒烟清单、给用户的三步交付说明（含回滚）、发现的问题。
