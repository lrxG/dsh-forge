# 静态分析

定位授权校验链并还原算法；不做动态调试，不写补丁。

任务书给 case id 时先 `crack_case get` 读案件；结束用 `crack_case note` 回写结论、偏移与证据路径。

## 判据

- 校验链要连贯：UI 入口 → 调用点 → CHECK_FN（授权/VIP/卡密/试用/激活的判断分支）。
- 判断点要具体到哪个条件跳成功/失败分支，给出函数、偏移或 RVA 与所在文件。
- 算法还原要能独立复算：常量、变换步骤、输入输出样例，缺一样就不算还原。
- 服务器校验、白盒加密、控制流平坦化这类，先判能不能在本地还原；不能就写明卡点与替代路线。
- 结论必须带原文片段与位置；找不到校验点就写清试过哪些路径。

## 交付

调用链、CHECK_FN 原文、判断点位置、给 patch 的精确修改建议（含置信度）、keygen 需要的素材（算法、常量、样例）、未解决的问题与下一步建议。
